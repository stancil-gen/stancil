How it works

One spec. All the structure.

Stancil reads your spec, runs a 6-stage pipeline, and writes every structural file into a read-only generated/ directory. Your business logic lives in hooks/ — a directory the tool never touches.

write → lock
🔒

generated/ is read-only

Every generated file is locked with chmod 444 and the macOS uchg immutable flag. You can't accidentally edit it. Run stencil generate to update it.

🪝

hooks/ is yours

The generator never reads or modifies hooks/. Every hook is optional — unset hooks are skipped. You only implement what the generator can't infer.

Quick start

Up and running in 5 steps

1

Install stencil

One command installs the binary to /usr/local/bin on macOS or Linux.

curl -fsSL https://raw.githubusercontent.com/stancil-gen/stancil/main/install.sh | sh
2

Write a spec

Describe your service in stancil.yaml — tables, databases, API endpoints, external HTTP clients.

version: 1
project: my-service
lang: go
framework: gin

config:
  - name: DATABASE_URL   type: str   required: true

db:
  - name: postgres
    driver: postgres
    framework: gorm
    url: ${DATABASE_URL}

tables:
  - name: tasks
    db: postgres
    fields:
      - name: title   type: str   required: true
      - name: done    type: bool  default: false

resources:
  - group: TaskAPIs
    base_path: /tasks
    apis:
      - name: CreateTask
        method: POST
        path: /
        dtos:
          request:
            name: CreateTaskRequest
            fields:
              - name: title   type: str   required: true
          response:
            name: CreateTaskResponse
            fields:
              - name: id      type: uuid
              - name: title   type: str
        steps:
          - id: writeTask
            touch: {table: tasks, op: create}
            fatal: true
3

Generate

Stancil writes all models, repos, handlers, services, DI wiring, and go.mod in under a second.

stencil generate stancil.yaml
4

Write your hooks

Implement only the business logic the generator can't infer — password hashing, response mapping, conditional logic.

// hooks/task_hooks.go
func (h *Impl) BeforeResponse(ctx context.Context,
    shared *task_ap_is.CreateTaskContext) error {

    shared.Response = &task_ap_is.CreateTaskResponse{
        Id:    shared.WriteTaskOutput.ID,
        Title: shared.WriteTaskOutput.Title,
    }
    return nil
}
5

Run

go mod tidy && go run main.go

Hooks

Business logic, precisely placed

Every API execution flows through a shared context struct. Generated code calls infrastructure and stores results on it. Your hooks read those results and decide what happens next.

hook BeforePlaceOrder — validate request, reject early without hitting DB or Stripe
↓ generated: call Stripe ChargeCard → result stored in shared.ChargePaymentOutput
hook AfterStripeClientChargeCard — log charge ID, handle non-fatal failure
↓ generated: insert order row → result stored in shared.WriteOrderOutput
hook BeforeResponse — combine charge ID + order ID into the response DTO 
// hooks/order_hooks.go — only the logic that matters

// Hash password before DB write — generated code can't do this
func (h *Impl) BeforeTableUsersCreate(ctx context.Context,
    shared *user_ap_is.CreateUserContext) error {

    hash := sha256.Sum256([]byte(shared.Request.Password))
    shared.WriteUserInput.PasswordHash = fmt.Sprintf("%x", hash)
    return nil
}

// Build response from two separate infra results
func (h *Impl) BeforeResponse(ctx context.Context,
    shared *order_ap_is.PlaceOrderContext) error {

    shared.Response = &order_ap_is.PlaceOrderResponse{
        OrderId:  shared.WriteOrderOutput.ID,   // from DB
        ChargeId: shared.ChargePaymentOutput.Id, // from Stripe
        Status:   string(shared.WriteOrderOutput.Status),
    }
    return nil
}

Hook fields that are nil are silently skipped by the executor — you only wire the ones you need.

Spec reference

Everything the spec supports

A stancil.yaml describes your entire service. Each block maps directly to generated code.

config — environment variables

config:
  - name: DATABASE_URL
    type: str
    required: true
  - name: PORT
    type: int
    default: 8080

db — database connections

db:
  - name: postgres
    driver: postgres    # postgres | mysql | mongo
    framework: gorm     # gorm | sqlx | sqlc
    url: ${DATABASE_URL}

tables — database tables

tables:
  - name: users
    db: postgres
    fields:
      - name: email    type: str   required: true   unique: true
      - name: password type: str   required: true   private: true
      - name: role     type: enum  values: [admin, user]
    queries:
      - find_by: [email]
      - paginate: offset
    errors:
      - code: NOT_FOUND   name: NotFound

externals — outbound HTTP clients

externals:
  - name: StripeClient
    type: http
    base_url: ${STRIPE_URL}
    auth: bearer_token
    timeout: 10s
    retry:
      attempts: 3
      backoff: exponential
      on_status: [429, 502, 503]
    calls:
      - name: ChargeCard
        method: POST
        path: /v1/charges
        body:
          name: ChargeRequest
          fields:
            - name: amount   type: int   required: true

resources — API endpoints

resources:
  - group: OrderAPIs
    base_path: /orders
    apis:
      - name: PlaceOrder
        method: POST
        path: /
        steps:
          - id: chargePayment
            touch: {external: StripeClient, method: ChargeCard}
            fatal: true
          - id: writeOrder
            touch: {table: orders, op: create}
            fatal: true
